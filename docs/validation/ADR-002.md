# ADR-002 profiling and validation

Date: 2026-10-17. Status: investigation and selected optimizations complete; performance parity remains open.

## What was measured

Windows 11, Intel Core Ultra 9 285K, Rust 1.89.0, opt-level 3, LTO, one codegen unit.
Each benchmark process was restricted to logical CPU 2. This is one logical CPU, not a claim
about P/E core placement or general hardware performance. Variants rotated execution order.
Release comparisons used five process samples, normally at least 750 ms each; the large-case
confirmation used seven samples of at least one second. Separate instrumentation used two
samples and is not used as evidence of a release speedup. Min/max ranges are in summary.json.
The common timed harness includes input reset and coordinate/gradient fingerprints as well as
the warmed solve. It is an end-to-end comparison, not isolated API dispatch latency.

Original means 9a200cb. Current means ca6baa5. No-fill removes only the sentinel fills.
Reuse caches the validated directional derivative and skips unused norm reductions.
Paired adds two independent scalar accumulators in one history traversal.
Isolated (selected) keeps that loop in a separate scalar function outside backend dispatch.
Equivalent-original gives the old driver the same numerical optimizations and sentinel policy.
Direct bypasses the public polling enum only in the callback adapter. Inline forces transition
inlining. The latter two were tested and rejected as inconsistent improvements.

## Findings

The initial 3.18% observation was a whole-benchmark difference on one unpinned case. It was
not an isolated measurement of the driver. Removing sentinel fills did not consistently recover
the difference across objectives, dimensions and backends. Retain incomplete-write detection.
Instrumentation placed most time in direction construction and history updates. Compact free-set
matrices and reduced-gradient/subspace products remain substantial hotspots. These coarse timers
do not identify a specific assembly instruction or prove the precise source of the remaining gap.

Two redundant operations existed in both old and new drivers: recomputing the directional
derivative and reducing a direction norm on iterations that never use it. Removing them is a
general speedup, not proof that resumability has zero overhead. Independent scalar products
can share a pass without changing either accumulator order or product operand order.

## Remaining equal-policy driver difference

The equal-policy comparison still shows a reproducible workload-dependent gap. Both drivers
use the same optimized numerical kernels and gradient sentinel policy. This narrows the issue
to driver organization and its compiled consequences, but does not isolate a machine-code cause.
The original-driver control is an experiment, not a second production implementation.

- n=25, deterministic: selected resumable driver +0.554% versus equivalent-original.
- n=25, faer: selected resumable driver +1.617% versus equivalent-original.
- n=1000, deterministic: selected resumable driver +1.424% versus equivalent-original.
- n=1000, faer: selected resumable driver +1.100% versus equivalent-original.
- n=100000, deterministic: selected resumable driver +6.535% versus equivalent-original.
- n=100000, faer: selected resumable driver +5.124% versus equivalent-original.

Later direct/inline controls put the large-case difference around 4-7%, with variation between
batches. Neither shortcut consistently removed it, so neither was adopted. The selected code
also remains 2.53% slower than the unoptimized original in the final 100,000-variable faer case.
Do not claim universal parity, a universal speedup, or that the overhead issue is fully fixed.

## Numerical and implementation validation

- PASS: all release experiment final x/gradient bit fingerprints, values, iteration and evaluation
  counts match within each backend/case across all tested variants. This is not a proof for all inputs.
- PASS: 136 percentage summaries independently recomputed with decimal arithmetic; absolute
  error <= 1e-10 percentage points. Raw sample ranges are preserved.
- PASS: independent Fortran trajectories, unchanged fixture hashes, protocol/cancellation tests.
- PASS: new bitwise scalar-product test covers ring positions, cancellation, mixed magnitudes and signed zeros.
- PASS: cached derivative equals the recomputed ordered dot product in the history-reset regression test.
- PASS: warmed callback and resumable allocation tests on deterministic/faer for m=2,10,20.
- PASS: stable scalar/all-feature and Rust 1.80 scalar/all-feature tests, strict Clippy/formatting and rustdoc.
- PASS: stable release all-feature suite (56 tests plus one doctest), and final package build verification.

## Follow-up

Preserve the public resumable API and one numerical engine. Inspect generated-code differences
between equal-policy drivers, including alias information, bounds checks and vectorization in
compact free-set and subspace loops. Candidate changes must retain operand/reduction order and
pass the same controls. Sampling/assembly profiling may narrow the remaining cause; no system-wide
profiler session was needed for the coarse profiling and controlled ablations performed here.
Scaling, alternate line search, approximate arithmetic and changed stopping policies remain out of scope.
